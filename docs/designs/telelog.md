## Problem Statement

The visualizer lists every function and its trace output is noisy. It does not explain the codebase in human terms. Telelog adds a human-meaning layer: the coding agent writes structured `@telelog` comment blocks above each function, and the visualizer reads them to build a stable nested map (project → feature → flow → function) with a tag-plus-trace detail panel. Full spec: the user's build prompt (grammar, MCP tool list, skill rules, UI levels, acceptance criteria).

## What Makes This Cool

The map shows features and data flow ("Checkout takes cart_id from the request body, reads carts, writes orders") instead of files, and the agent maintains it as a side effect of editing code. The detail panel joins the declared contract with live trace values, so the map doubles as a living contract checker.

## Constraints

- Tags are `#` comments only: no decorators, no imports, no runtime effect. The parser uses `tokenize`/regex plus `ast` and never executes or modifies target code.
- Tag id is `module.path::qualname`. Existing function ids in this repo are `module:QualName` (`backend/analysis/models.py`). Telelog needs an id mapping or must standardize on one form.
- Already in the repo and overlapping with telelog:
  - `backend/analysis/mapmodel.py` scores functions as main or helper (`score_function`), and `pin_function` overrides the score.
  - `backend/analysis/algorithm.py` has fills cached per function against a body hash (`body_hash`, `validate_fill`) with a `stale` status, plus MCP tools `get_map`, `get_algorithm`, `write_algorithm`, `pin_function`.
- No DB. State follows the house pattern: JSON under a cache dir, atomic write. Telelog state (body hashes, progress) goes in the target's `.telelog/`, outside source files.
- Visualizer is read-only. Only the agent edits target comments.
- Reference UI `project_map.html` was not attached. Until it is, the existing `MapView.tsx` is the style baseline.

## Premises (all confirmed)

1. Telelog `role` is the source of truth where a tag exists, replacing the automatic main/helper score and making `pin_function` redundant for tagged functions. Untagged functions fall back to the score and are visibly marked.
2. `write_algorithm` cards stay for step-level detail. The tag's `algo:` line is a ≤7-step summary only, to avoid two divergent descriptions of one function.
3. Live sample values appear only for declared fields that match a traced argument name or return key. Declarations like `cart.items (db:carts)` show without a sample. No guessing.
4. The wedge is parser, `validate_tags`, and a tag-driven map, built before the MCP tools, skill, or hook.
5. Every function gets a tag, helpers as one line. The accepted cost is tag churn on every edit.

## Recommended Approach

Approach A, then the remaining spec steps in order.

Milestone 1, the demoable slice:
1. Tag grammar + parser (`backend/analysis/telelog.py` or similar): header `key=value` line plus `key: value` lines, bound to functions via `ast` line numbers. Edge cases: async, stacked FastAPI decorators, nested functions, methods, blank lines or comments between block and `def`.
2. `validate_tags`: missing, orphan, duplicate id, unknown parent, bad field, over-cap, unknown source vocabulary; warnings for stale (body hash), renamed (same body, new id), `purpose: ?`. Reuse `algorithm.body_hash`.
3. Merge tags into `build_map`. `role` and `feature` override the score. Add `feature`, `parent`, `n`, `in`/`out`/`db` to the map payload.
4. Nested map UI in `MapView.tsx` / `mapLayout.ts`: Project (feature cards) → Feature (flows) → Flow (ordered steps by `parent` and `n`) → Function (helpers and real call graph), plus a one-click switch to the existing deterministic view.
5. Detail panel: role badge, purpose, in/out filled from the trace, DB r/w, algorithm for mains, tag health. Redact sensitive-looking sample values.
6. Hand-tag about 10 functions in `sample_project` to exercise every level.

Milestone 2: MCP tools (`list_untagged`, `get_function`, `get_feature_tree`, `validate_tags`, `suggest_parent`, `check_changed`, `record_progress`/`get_progress`) added to `backend/mcp_server.py`, following the pattern of existing tools.

Milestone 3: `telelog` SKILL.md with `/telelog` audit mode, and the `PostToolUse` hook that calls `check_changed`.

Milestone 4: trial on a real FastAPI project (about 200 functions); tune caps and token budget.

## Open Questions

- **Id form:** keep `module:QualName` internally and translate to `module.path::qualname` for tags, or change tag format? Pick one before the parser lands.
- **Data-flow edges (8.4):** declared `in` sources of the form `step:<function>` give edges directly. Decide whether edges come only from declarations or also from the call graph when they disagree.
- **Loops and conditionals in `n` ordering:** unresolved from the spec. Proposal: same `n` for parallel steps; conditional steps get a `?` suffix later, if needed.
- **Does `purpose: ?` block the audit summary** or only warn? Proposal: warn only, list in the summary.
- **Excluded paths config format** for `.telelog/config` (tests, migrations, generated).
- **`project_map.html`** still needs to be attached for the visual reference.
- **Caps** (tags per feature, fields per function): tune after the first trial.

## Success Criteria

- `/telelog` on a FastAPI project leaves zero missing-tag errors from `validate_tags`.
- Renaming or moving a function produces a "renamed" warning, not a silent loss of its tag.
- Editing a function without updating its tag is caught by the hook.
- The top-level map shows features, not files; drilling down reaches individual functions.
- The detail panel shows only declared fields, filled with live values when a trace exists.
- A medium project (about 200 functions) audits in bounded batches with resumable progress.
- The parser never executes or modifies target code.
- Milestone 1 specifically: hand-tagged `sample_project` renders all four map levels and a detail panel with live values.

  - Redact sample values by source (`JWT`, `header`) and by name pattern (password, token, secret, card, authorization, cookie).
  - `list_untagged` cursor is the last id returned over a stable sort, not an offset.
  - Cache the tag index per analysis generation, like `_db_index`; detail panel uses the latest trace per function; `get_function` caps source length.
  - Distribution: each target's `.mcp.json` needs the `brain-telemetry-*` server.
